## Question

会话结束后的自动记忆抽取（Q9C + Q18B：会话 ≥8 轮才抽，异步）的落地规则：

1. 抽取范围：只抽关于用户的陈述（偏好/事实/承诺），还是也抽对话中出现的知识三元组？
2. 去重：新记忆与已有记忆如何判断重复（token 相似度阈值？实体重合？）
3. 重要度打分：谁打分（LLM 自评 vs 规则），默认重要性阈值多少？
4. 失败与降级：无 API key 时回退 RuleExtractor（Q24 已定），具体哪些能力降级、哪些停用？
5. 抽取结果是否可被用户事后查看/删除？（影响 UI 决策）

## Resolution

诘问一轮定案（2026-09-05）：

1. **范围与调用**：会话结束抽取一次 LLM 调用，返回结构化 JSON（facts + triples 两数组，schema 约束）；用户陈述 → 记忆，通用概念关系 → 三元组
2. **去重**：记忆条目 token 相似度 ≥0.85 判重（与矛盾检测同阈值），命中不覆盖只 `touch` 提分；三元组用 head+rel+tail 结构判重（`_dedupe`）
3. **重要度**：LLM 自评 importance 1~10 + 规则兜底；**入库阈值 ≥3**
4. **降级**：无 API key 时对话抽取整体停用（靠 agent 主动 `remember`），文档抽取照常走 RuleExtractor
5. **可见性**：首版做轻量入口——设置面板"记忆"列表（查看/删除/手动添加）；图谱可视化不做（留 fog）
6. **时机**：聊天窗关闭时异步触发（≥8 轮才抽），不阻塞 UI，完成后气泡提示"已记住 N 件新事"
