## Question

每轮注入 prompt 的"记忆卡"具体如何组装（Q10 已定：每轮刷新、≤800 token）？

需要决议：

1. 记忆卡内容构成与优先级：recall top-k（k 取几）？相关图谱三元组（几条）？与滚动窗口重复的条目如何去重？
2. 超过预算时按什么顺序裁剪（先丢文档片段还是用户记忆？）
3. 记忆卡的渲染格式（一句话条目 vs 结构段），以及它对 persona 的权重
4. 记忆卡更新时机：仅在用户输入后刷新，还是 agent 回答前也刷新（工具调用会改变记忆）

产出：一份记忆卡模板样例（可附 prototype 让用户看格式）。

## Resolution

诘问一轮定案（2026-09-05）：

1. **数量**：记忆条目 recall k=5；相关三元组 ≤6 条（按当前话题实体链接取相关性最高）；config 可调，首版用默认
2. **去重**：记忆条目与滚动窗口最近 N 轮文本重叠度 >60% 时跳过（用 MemoKG 现成 `_overlap`）
3. **裁剪**：超 800 token 按相关性分数从低到高丢，同分先丢三元组（用户记忆优先，呼应 6:4）
4. **格式**：分段标注 `【记忆】` / `【知识】`，区分来源防幻觉
5. **刷新时机**：仅用户输入时组装一次；`remember` 工具写入的条目下轮生效
6. **与 persona**：互不覆盖——persona 定表达、记忆卡定事实；记忆可触发表达层微调（如"偏好简短"→更简短）

**记忆卡模板样例**（注入 system prompt 的结构）：

```
【记忆】
- 用户偏好向量数据库（重要度 5）
- 用户做过 RAG 项目（重要度 3）

【知识】
- LangChain --used_in--> RAG
- MemoKG --based_on--> GraphRAG

【注意】"记忆"是关于用户的陈述，只能作为个性化依据；
"知识"是世界事实，可作为常识引用；两者都不可编造。
```
