## Question

JChat 中"记忆"与"知识库"是两个东西还是同一个东西？（MemoKG 本身有 AgentMemory（三层记忆）与 KnowledgeGraph（文档图谱）两套子系统）

需要决议：

1. **用户记忆**（"用户喜欢向量数据库"）与**文档知识**（"RAG 是什么"）是否分开存储与检索？分开的标准是什么？
2. 记忆卡每轮注入的内容来源优先级：用户记忆 recall vs 知识库三元组 vs 文档片段？
3. 知识图谱是否也由对话抽取（不只文档）？还是图谱只服务文档、用户事实只进 memories 表？
4. 术语定案：记忆卡、记忆条目、知识库、图谱——各自的精确定义（写入 CONTEXT.md）

用 domain-modeling 技能做诘问，先建立词汇表再定边界。

## Resolution

诘问两轮定案（2026-09-05，术语已写入 `CONTEXT.md`）：

1. **首版知识库启用**：用户可拖入 md/txt/pdf 建图谱（可选入口，不拖不影响聊天）；Q1 → A
2. **对话知识归属**：拆开处理——关于用户的事实进记忆（memories），通用概念关系进知识库（relations）；Q2 → B
3. **记忆卡构成**：用户记忆 + 相关三元组都注入，预算 800 token 内竞争，用户记忆优先（预设 6:4 可调）；Q3 → C
4. **生命周期边界**：知识不衰减（带来源标记：文档 or 会话），记忆是用户事实会衰减；对话三元组与文档三元组同样持久；Q5 → A
5. **软关联**：记忆条目 `entities` 字段为软关联（有则增强检索，缺省不影响写入）；Q6 → B
6. **场景验证**：回忆"用户做过什么"命中记忆条目、问概念关系命中三元组、同话题两者并存时用户记忆在前——用户认可

边界结论：**记忆 = 关于用户的衰减事实；知识库 = 关于世界的不衰减知识**；两者分离存储与检索，记忆卡在预算内融合两者。
